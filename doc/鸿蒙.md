## 二、分类详解

### 2.1 应用框架与 UI 类：ArkTS + ArkUI 声明式开发与一多部署

**技术要点**

- 采用 **ArkTS** 作为开发语言，在 **ArkUI 声明式开发范式**下通过 `@Component` / `@Entry` 构建页面，配合 `@State` / `@Prop` / `@Link` / `@Observed` 状态管理驱动界面刷新。
- 使用 **一次开发、多端部署** 能力：基于 `GridRow` / `GridCol` 栅格布局 + 响应式断点（`mediaquery`）适配手机、折叠屏、平板与车机，一份代码多形态渲染。
- 结合系统级无障碍能力：`accessibilityLevel` / `accessibilityText` 语义标注 + 跟随系统 `fontScale` 的字号缩放，实现全局字号放大与高对比度。

**作品落地**

- 游客端"普通 / 银发 / 童趣"三模式切换：银发模式放大全局字号、提升对比度、简化操作路径；童趣模式切换卡通配色与图形化导航。
- 首页、景点列表、AI 问答、路线规划、FM 广播等页面均以声明式组件构建，保证多端一致的交互体验。

**技术价值**

- 一套代码覆盖多设备形态，显著降低多端维护成本；系统级无障碍能力使适老化改造从"界面放大"升级为"全链路可读、可听、可操作"。

---

### 2.2 AI 多模态交互类：Core Vision Kit + Core Speech Kit

**技术要点**

- **Core Vision Kit**：调用端侧 `textRecognition`（通用文字识别）、`subjectSegmentation`（主体分割）、`faceDetector`（人脸检测）等能力，对摄像头采集的图像做本地预处理与结构化提取。
- **Core Speech Kit**：`speechRecognizer` 实现端侧语音识别（语音输入导览提问），`textToSpeech` 实现文本转语音播报（数字人讲解、FM 广播）。
- 端侧完成识别与合成后，仅将结构化文本上传云端大模型，减少图像/音频原始数据上传，兼顾响应速度与隐私安全。

**作品落地**

- **VR 即拍即识**：游客拍摄碑刻、雕塑、古树后，端侧先做主体分割与文字提取，再交由多模态大模型输出文物解读，实现"即拍即讲"。
- **AI 数字人问答**：语音提问 → 端侧 STT 转写 → Hybrid RAG 检索问答 → 端侧 TTS 播报，形成免手持的语音导览闭环。
- **景区 FM 广播**：讲解文稿经端侧 TTS 合成，支持后台播放与锁屏控制。

**技术价值**

- 端云协同的 AI 链路降低了对网络的强依赖，在景区弱网环境下仍可完成识别与播报，端到端交互时延可控。

---

### 2.3 分布式协同类：分布式软总线、跨端迁移与分布式数据对象

**技术要点**

- 基于 **分布式软总线** 实现设备间自发现、自组网与低时延传输，无需数据线或手动配对。
- 使用 **跨端迁移（Continuation）** 能力：在 `UIAbility` 中实现 `onContinue` / `onCreate` 数据接续，导览会话可从手机无缝流转至平板或车机。
- 通过 **分布式数据对象**（`distributedDataObject`）在可信设备间同步会话状态、路线进度与游览足迹，保证多端数据一致。

**作品落地**

- 游客在手机上与数字人"小玉"对话、规划路线，上车后可一键流转到车机继续导览，讲解进度、当前景点与偏好模式完整保留。
- 同行家人的多台设备可共享同一条游览路线与打卡进度，实现"一人规划、多人同步"。

**技术价值**

- 将单设备导览升级为"跨设备连续服务"，契合景区游览中手机—平板—车机多场景切换的真实动线。

---

### 2.4 元服务与卡片类：元服务（原子化服务）+ 万能卡片

**技术要点**

- 以 **元服务** 形态交付核心导览能力：免安装、服务直达，用户扫码或碰一碰即可进入 AI 导游。
- 通过 `FormExtensionAbility` + `@kit.FormKit` 开发 **万能卡片**，支持 2×2 / 4×4 等多种规格与定时刷新，卡片数据可由服务端 RPC 动态下发。
- 卡片支持点击直达指定页面（`router` 跳转），并可按景区、时间、客流状态动态切换展示内容。

**作品落地**

- 桌面卡片展示"今日推荐景点 / 实时客流 / 待打卡足迹"，点击直达景点详情或 AI 问答。
- 景区入口二维码 + 元服务卡片组合，替代传统"下载 App—注册—找入口"的长链路。

**技术价值**

- 大幅降低游客首次使用门槛，把"打开应用"变成"服务就在桌面"，适配景区短时、高频、即来即走的使用特征。

---

### 2.5 位置与地图类：Location Kit + Map Kit

**技术要点**

- **Location Kit**：`geoLocationManager` 获取实时定位与持续定位；`geofenceManager` 设置地理围栏，进入/离开景区关键点位时触发提醒。
- **Map Kit**：`MapComponent` 渲染景区地图与景点标注，结合路线规划能力呈现步行路径；支持自定义 Marker、图层与缩放交互。
- 服务端以球面距离算法（Great Circle Distance）完成景点间距测算与路线排序，端侧负责实时位置纠偏与偏航提示。

**作品落地**

- 智能路线规划：按兴趣标签、游览时长、无障碍需求生成路线，在地图上可视化呈现并实时高亮下一站。
- 地理围栏：游客偏离推荐路线或接近景点时，数字人主动播报提示，实现"走到哪、讲到哪"。
- 银发模式优先推荐平缓无阶梯路线，位置服务与路线策略联动。

**技术价值**

- 位置能力与 AI 导览深度耦合，使静态图文讲解升级为"空间感知 + 主动服务"的沉浸式体验。

---

## 三、技术亮点小结

1. **端云协同的多模态链路**：Core Vision Kit / Core Speech Kit 承担端侧识别与合成，云端大模型负责理解与生成，兼顾时延、隐私与弱网可用性。
2. **一多部署 + 全链路无障碍**：ArkUI 响应式布局与系统无障碍属性结合，一套代码同时满足普通游客、银发人群与儿童三类用户。
3. **跨设备连续服务**：分布式软总线 + 跨端迁移把游览从"单设备 App"变成"多设备接力"，贴合景区真实游览动线。
